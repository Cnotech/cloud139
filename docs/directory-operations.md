# 目录操作实现与验证

## 协议依据与限制

使用项目 main `353bbf79bb54585742133247b6309234be089de9` 已有个人盘端点，并核对公开的 [AlistGo/alist 139 driver](https://github.com/AlistGo/alist/blob/main/drivers/139/driver.go) 与 [目录列表实现](https://github.com/AlistGo/alist/blob/main/drivers/139/util.go)（核对日期 2026-11-17）。只借助公开代码核验请求字段，没有使用真实 139 凭证或请求真实盘数据。

- 个人盘使用 `/file/create`、`/file/batchCopy`、`/file/batchMove`、`/file/update` 和 `/recyclebin/batchTrash`。
- 家庭云、和家亲、群组盘及其他存储类型统一返回“未实现：当前仅支持个人云”。
- `rm --yes` 将文件移到回收站。目录还需指定 `-r`。

## 路径映射和操作行为

`upload ./dir /dest` 保留目录本身，落在 `/dest/dir`；`upload ./dir/ /dest` 仅上传内容，落在 `/dest`。两种映射均保留空目录。复用 sync 本地扫描和底层单文件上传，始终计算并提交文件哈希，不采用 `compute_diff` 的大小判断。已有同名文件默认报错；`--force` 允许上传同名文件，新文件使用服务端分配的名称，原文件保留。

`download -r /dir ./new-name` 将目录内容存入 `./new-name`；目标已是目录或参数末尾有 `/` 时，在其下创建源目录名。远程根目录默认保存到 `download`。不带 `-r` 下载目录失败。现有普通文件可以写入，但不能通过符号链接写入，也不能把目录覆盖为文件。递归计划先完整扫描并校验名称、重复名称、本地类型冲突与现有路径的符号链接，再开始写入。

递归下载根据目标文件系统检测大小写及 Unicode 等名称冲突。每个文件完整下载到同目录临时文件后才替换目标，单个文件断流会保留该文件原内容。

`mkdir -p` 创建所有缺失父目录，已有目录成功，同名文件失败；不带 `-p` 要求父目录存在，且最终目录不存在。创建后重新解析并检查目录名称和类型，避免误用重命名后的 ID。

`ls -R` 返回所有目录的完整内容，包括空目录；JSON 为目录对象数组。普通 `ls` 的 JSON 保持原对象格式。分页游标循环会报错；递归遍历拒绝重复目录 ID、深度超过 256 和条目超过 100000。

所有变更操作都规范化 `/`、重复斜杠、`.` 和 `..`，再检查根目录和自身/子目录。远程名称按跨平台本地路径约束检查（包括 Windows 设备名、反斜杠、冒号、控制字符）。复制/移动先预检全部源、目标目录和名称冲突，再发出变更。`--force` 不覆盖目录类型冲突。批量响应中的条目级 `success: false` 会使操作失败。

递归任务可能部分完成；发生错误返回失败，不自动回滚。除下述个人盘目录上传的逐文件处理外，遇到错误停止执行。路径检查拒绝已存在的 symlink；本工具不提供与其他进程并发替换本地路径的沙箱隔离保证。

个人盘所有文件 API 请求统一发送 `X-Yun-Client-Info` 类型 `13`（PC），路由和登录续期维持原协议。参考 [AList 的 PC 客户端标识实现](https://github.com/AlistGo/alist/commit/33edee2a0dd774293d6d955407579ff7ceec05c1)；其余渠道、设备、签名字段保持一致。现有配置与浏览器获取的 Authorization 可继续使用，无需新增登录参数。上传权益由服务器判断，不固定拦截 5 GiB 或承诺所有账号都支持 500 GB。

个人盘目录上传遇到权益不足或其他普通文件失败时继续后续文件，最后汇总成功与失败，有失败项返回非零；目录创建等结构性错误仍停止。

本地到个人盘 sync 先以唯一临时名称上传，上传完成后按服务端返回的文件 ID 和名称回读确认，再将旧同名条目重命名为备份。新文件改为原名并回读确认后才回收旧备份。替换阶段失败会报告临时或备份名称以便手动恢复。`--delete` 会保留 `.cloud139-upload-` 和 `.cloud139-backup-` 开头的恢复条目及其上级目录。用文件替换同名云端目录需要递归扫描该目录，包含排除条目或恢复条目的目录会报冲突。`--delete` 会保留待替换目录的后代，直到替换成功。dry-run 仅展示计划（含已知冲突），正常返回 0；有执行失败项返回 1。

云端到本地 sync 优先使用扫描得到的文件 ID 和大小，避免逐个文件重查父目录；下载失败继续使用已有的请求级重试。路径仍按扫描时的名称映射到本地。同步传输前先完成目录创建，同名类型冲突会保留原条目。云端到本地复用递归下载的大小写和 Unicode 路径冲突检查。本地到云端复用已确认的父目录 ID，发布前复核目标目录的路径和 ID。普通同步在传输全部成功后才清理，逐项复核扫描对象，先处理子项，再删除确认已空的目录。

`--verify` 校验同大小的现有文件和所有新上传的临时副本。对比远端可用的 SHA-256 或读取远端内容计算哈希，随后复用安全替换流程。与 `--delete` 同用时，初始扫描确定多余文件范围，校验通过后按父目录核对文件名和 ID，再按 ID 回收。校验、复核或目录创建失败时保留多余文件。校验模式保留多余目录，也保留与本地目录同名的云端文件并报告冲突。清理按文件提交，每次回收前再次核对该文件。发现变更或收到回收错误时停止余下请求。

## 离线与 mock 测试

`tests/directory_operations_test.rs` 使用状态化 loopback HTTP mock，覆盖目录与内容映射、缺失父目录、空目录、同大小文件不跳过、目录下载需 `-r`、全部分页、游标和目录循环、根别名、自身/子目录、目标类型、文件冲突、部分失败、恶意名称、Unix symlink。

`tests/storage_support_test.rs` 验证 CLI 命令及 API 入口对非个人盘配置返回统一错误。

测试不读取真实配置。完整测试前先审查测试中已有网络调用；所有凭证为虚构，使用临时 HOME/XDG_CONFIG_HOME，HTTP_PROXY/HTTPS_PROXY/ALL_PROXY 指向不可用 loopback 端口，并仅对 localhost/127.0.0.1/::1 免代理。Cargo 先单独获取锁定依赖，然后使用 `--locked --offline` 测试。仓库 E2E 技能需要真实 Token 和云端写入，本次不执行。

```bash
cargo fmt --all -- --check
cargo test --workspace --locked --offline --no-fail-fast
cargo clippy --workspace --locked --offline --all-targets
```
