# 个人云目录操作与验证

cloud139 的文件操作支持 `personal_new`。创建、复制、移动、重命名和回收分别使用 `/file/create`、`/file/batchCopy`、`/file/batchMove`、`/file/update` 和 `/recyclebin/batchTrash`。个人云文件 API 使用类型为 `13` 的 PC 客户端标识，上传大小上限由服务端按账号判定。见[协议常量](../packages/lib/src/protocol.rs)、[请求头定义](../packages/lib/src/client/api/headers.rs)和 [AList 139 驱动](https://github.com/AlistGo/alist/blob/main/drivers/139/driver.go)。

## 路径映射与递归操作

| 操作 | 行为 |
| --- | --- |
| `upload ./dir /dest` | 上传目录本身，结果在 `/dest/dir`。 |
| `upload ./dir/ /dest` | 仅上传 `dir` 的内容。两种目录上传都保留空目录，并创建缺失的云端目标目录。单文件上传要求目标目录已存在。 |
| `download -r /dir ./new-name` | 目标不存在时，直接将目录内容写入 `./new-name`。目标已是目录或参数以 `/` 结尾时，在目标下追加源目录名。下载云端根目录且省略本地目标时，默认使用 `./download`。 |
| `mkdir -p /a/b` | 创建缺失的父目录和目标目录，已有目录视为成功，同名文件会报错。省略 `-p` 时要求父目录存在且目标目录尚未创建。 |
| `ls -R /dir` | 读取各目录的全部分页，包括空目录。使用 `-o` 时写入目录对象数组，普通 `ls -o` 写入单个分页对象。递归遍历会拒绝循环游标、重复目录 ID、深度超过 256 或条目超过 100,000 的结果。 |
| `rm --yes /file` | 将文件移到回收站，目录还需加 `-r`。 |

- 目录上传按文件计算并提交哈希。同一父目录的同名检查复用首次读取的条目，并补充本次操作确认的名称。已有同名文件默认报错，`--force` 允许云端为新文件分配名称，保留原文件。其他客户端在上传期间新增的同名条目由服务端处理。单文件失败后继续处理其余文件，云端写入失败后会在下次处理同一父目录时重新读取。创建目录失败则停止，已完成的条目保留。
- 递归下载在写入前校验整棵目录的名称、目标类型、大小写和 Unicode 名称冲突，以及本地符号链接。每个文件先写到同目录临时文件，完整下载且通过可用的字节数校验后才替换目标。失败时保留该文件的原内容，并停止后续下载。路径检查以检查时看到的本地状态为准。
- 复制和移动要求目标目录已存在，并在提交前检查全部源条目、重复名称及路径冲突。批量预检在本次命令内复用已读取的目录分页。路径规范化后拒绝把根目录作为源，也拒绝把目录复制或移动到自身及其子目录。涉及目录的同名冲突即使加 `--force` 也会报错。批量响应中的条目级失败会使命令返回失败。服务器接受任务后，实际结果可通过再次列出目标目录确认。
- 重命名只接受新名称，不能借此移动条目。源名称与新名称相同且条目存在时，命令成功且保持原条目。删除和重命名均拒绝操作根目录。

## 同步与清理

- 云端同步根目录必须已存在。普通同步先创建所需目录，再传输文件。个别操作失败时继续处理其余文件，只有建目录和传输全部成功才开始清理。清理前逐项复核扫描对象，先处理子项，再删除确认已空的目录。发现变更或删除失败时停止后续清理。
- 本地到云端同步先上传临时副本，再确认文件 ID 和名称。替换旧条目时先将其改名为备份，新文件改成目标名称并确认后才回收旧备份。替换期间云盘需要容纳新旧两份内容，失败时可按报错找回临时文件或备份。`--delete` 会保留以 `.cloud139-upload-` 或 `.cloud139-backup-` 开头的云端恢复条目及其上级目录。用文件替换同名云端目录时，需递归扫描并复核整个待替换目录，含有排除或恢复条目时拒绝替换。
- 云端到本地同步使用扫描得到的文件 ID 和大小下载，保留路径映射，并在传输前检查大小写和 Unicode 名称冲突。下载复用请求级重试与临时文件替换。本地目标发生文件与目录类型冲突，或本地目录与云端同名文件冲突时，同步会保留原条目并报告错误。
- `--verify` 仅支持本地到云端，并发固定为 1。它基于初始扫描校验同大小的现有文件，缺少可比的远端 SHA-256 时按扫描得到的文件 ID 读取内容计算哈希，可能增加下载流量和耗时。上传前复核目标，替换前校验临时副本。
- `--verify --delete` 要求范围内至少有一个源文件。校验和更新全部成功后，只回收初始扫描中多余的文件。清理前复核待删除文件所在目录里保留文件和待删除文件的 ID 及扫描时记录的元数据。回收每项前再次确认完整路径并核对 ID 和名称。发现变更或删除失败时，已完成的删除保留，剩余删除停止。
- `--dry-run` 展示同步计划，成功生成计划时退出码为 0，即使计划包含冲突。参数校验或计划生成失败时退出码为 2，实际执行中的操作失败返回 1。预览仍会扫描目录，CLI 也可能按需续期凭据。

### JSON 同步报告

`--json` 在执行或预览结束后向标准输出写一行同步报告，日志写到标准错误。普通同步和 `--verify` 均支持该选项。

- `source` 和 `destination` 是传给命令的源路径和目标路径。`changes` 列出目标端已确认的文件变更，每项包含相对路径 `path` 和操作 `action`（`upload`、`download` 或 `delete`）。用文件替换云端同名目录时，原目录下移出目标路径的文件也计入删除。
- `-n` 将 `dryRun` 设为 `true`，预览操作写在 `plan` 中，`changes` 为空。待校验的文件用 `verify` 标记，上传、下载和删除计数表示计划中的文件数。
- `objects` 是源文件数，`uploaded`、`downloaded`、`deleted` 和 `skipped` 按文件计数。`hashMissing` 是因缺少可比哈希而需要读取云端内容的文件数，`seconds` 是执行或预览用时。
- `failures` 的每项包含 `path`、`error` 和 `retries`。执行中有操作失败时，报告仍包含已确认的变更，命令返回退出码 1。参数、配置或初始扫描报错时，通过标准错误和退出码查看原因。

## 验证

[目录操作测试](../packages/cli/tests/directory_operations_test.rs)使用本地 HTTP mock 检查路径映射、分页、名称冲突、部分失败和同步清理。[存储类型测试](../packages/cli/tests/storage_support_test.rs)验证 CLI 和库入口拒绝非个人云配置。

```sh
cargo test --locked -p cloud139-cli --test directory_operations_test --test storage_support_test
```

依赖已缓存时可使用 `--offline`，测试仍需监听本地回环端口。[E2E 技能](../.agents/skills/cloud139-e2e-test/SKILL.md)记录真实个人云回归和本地夹具流程。
