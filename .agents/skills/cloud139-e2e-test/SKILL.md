# cloud139 CLI 端到端回归

- **维护用例**：对照 [CLI 参数](../../../packages/cli/src/cli.rs)、`--help`、服务代码和测试断言，更新受影响的步骤和预期。用虚构数据核对即可。
- **离线验证**：读[本地测试与故障用例](references/offline.md)。使用临时配置和本地 HTTP mock。根目录误操作、已移除的参数、恶意名称、符号链接、循环分页和故障注入都在离线测试。
- **真实 E2E**：用户要求真实测试时，先读[准备、验证和清理](references/real-run.md)，再按范围选用例。只支持个人云 `personal_new`。写操作限于本轮登记的 UUID 子树和临时目录。使用用户提供的测试 Token 与独立配置，报告和日志里省略凭据。
- **请求日志**：真实 E2E 的每次 `cloud139` 调用都由统一入口附加 `--log-file`，包括登录、准备、轮询、核验、预期失败和清理。全部用例结束后合并为一份日志，检查异常和过频请求，再清理临时目录。见[日志收集与分析](references/real-run.md#日志收集与分析)。

真实测试以退出码、路径清单和逐文件 SHA-256 判定。服务端接受任务后，用后续读取确认最终结果。依赖用例失败时标为阻塞。报告区分本次通过、失败、阻塞、未运行和没有自动化断言的用例。

命令行为见[目录操作与验证](../../../docs/directory-operations.md)。保留用例编号以便定位断言和追踪失败。
